# SmartStock 智能库存管理助手 - 需求文档

## 1. 项目概述

### 1.1 项目愿景
SmartStock 是一个轻量级的全栈库存管理应用 MVP，旨在通过 AI 驱动的"规范驱动开发"模式，验证 Chrome MCP 与 MySQL MCP 的协同自动化能力。

### 1.2 目标用户
- 仓库管理员
- 库存管理人员

### 1.3 技术栈
- 前端：Next.js (App Router) + Tailwind CSS
- 后端：Node.js + Express
- 数据库：MySQL
- 认证：JWT
- 语言：全栈 TypeScript

## 2. 功能性需求

### 2.1 用户认证模块 (FR-AUTH)

#### FR-AUTH-001: 用户登录
作为系统用户，我希望通过用户名和密码登录系统，以便访问库存管理功能。

**验收标准：**
- AC1: 用户可以在登录页面输入用户名和密码
- AC2: 系统验证凭据正确后，生成 JWT Token 并跳转至仪表盘
- AC3: 凭据错误时，显示"用户名或密码错误"提示
- AC4: JWT Token 应包含用户ID、角色信息，有效期为24小时
- AC5: 未登录用户访问受保护页面时，自动重定向至登录页

#### FR-AUTH-002: 用户登出
作为已登录用户，我希望能够安全登出系统，以保护账户安全。

**验收标准：**
- AC1: 点击登出按钮后，清除本地存储的 JWT Token
- AC2: 登出后自动跳转至登录页面
- AC3: 登出后的 Token 不能再用于访问受保护资源

#### FR-AUTH-003: 密码重置
作为用户，我希望能够重置密码，以便在忘记密码时恢复账户访问。

**验收标准：**
- AC1: 用户可以通过"忘记密码"链接进入密码重置流程
- AC2: 输入用户名后，系统生成重置链接（MVP阶段可简化为直接重置）
- AC3: 新密码设置成功后，提示用户使用新密码登录

**验收标准：**
- AC1: 可在商品编辑页面设置预警阈值
- AC2: 阈值必须为非负整数
- AC3: 设置后立即生效，低于阈值的商品自动标红

### 2.6 入库管理模块 (FR-IN)

#### FR-IN-001: 单个商品入库
作为管理员，我希望录入单个商品的入库信息，以便更新库存数量。

**验收标准：**
- AC1: 可通过输入框输入SKU，系统自动匹配商品信息

- AC5: 提交后，商品库存数量增加相应数量

- AC4: 一次性提交所有入库记录
- AC5: 提交前验证所有行数据的完整性和正确性
- AC6: 部分行验证失败时，高亮显示错误行，不提交任何数据
- AC7: 全部验证通过后，批量更新库存并生成审计日志

#### FR-IN-003: 入库记录查看
作为管理员，我希望查看历史入库记录，以便追溯入库情况。

**验收标准：**

## 3. 非功能性需求

### 3.1 安全性需求 (NFR-SEC)

#### NFR-SEC-001: JWT认证
- 所有API请求（除登录外）必须携带有效的JWT Token
- Token过期后，返回401状态码，前端自动跳转登录页

#### NFR-SEC-002: 密码存储
- 用户密码必须使用bcrypt加密存储
- 禁止明文存储密码

#### NFR-SEC-003: SQL注入防护
- 所有数据库查询必须使用参数化查询
- 禁止拼接SQL字符串

### 3.2 可用性需求 (NFR-USA)

#### NFR-USA-001: 浏览器兼容性
- 支持 Chrome 90+ 版本
- 支持 Edge 90+ 版本

#### NFR-USA-002: 响应式设计
- 最小支持宽度：1280px
- 不需要移动端适配

#### NFR-USA-003: 界面风格
- 简洁清新风格
- 多巴胺配色方案（低饱和度）
- 仅支持中文界面

### 3.3 可维护性需求 (NFR-MNT)

#### NFR-MNT-001: 代码规范
- 使用 TypeScript 严格模式
- 遵循 ESLint 规范

#### NFR-MNT-002: 架构设计
- 前后端分离架构
- RESTful API 设计
- 支持未来扩展多角色权限

### 3.4 可测试性需求 (NFR-TST)

#### NFR-TST-001: MCP自动化测试支持
- HTML结构清晰，便于Chrome MCP识别Selector
- 关键元素添加data-testid属性
- 数据库通过MySQL MCP可访问

## 4. 数据模型

### 4.1 用户表 (users)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键，自增 |
| username | VARCHAR(50) | 用户名，唯一 |
| password | VARCHAR(255) | 密码（bcrypt加密） |
| role | VARCHAR(20) | 角色 |
| status | TINYINT | 状态：1启用，0禁用 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

### 4.2 商品分类表 (categories)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键，自增 |
| name | VARCHAR(100) | 分类名称 |
| parent_id | INT | 父分类ID，NULL为顶级 |
| created_at | DATETIME | 创建时间 |

### 4.3 商品表 (products)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键，自增 |
| sku | VARCHAR(50) | SKU编码，唯一 |
| name | VARCHAR(200) | 商品名称 |
| category_id | INT | 分类ID，外键 |
| unit | VARCHAR(20) | 单位 |
| quantity | INT | 库存数量 |
| min_threshold | INT | 预警阈值 |
| cost_price | DECIMAL(10,2) | 成本价 |
| sale_price | DECIMAL(10,2) | 售价 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

### 4.4 供应商表 (suppliers)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键，自增 |
| code | VARCHAR(50) | 供应商编码，唯一 |
| name | VARCHAR(200) | 供应商名称 |
| contact | VARCHAR(100) | 联系人 |
| phone | VARCHAR(20) | 联系电话 |
| address | VARCHAR(500) | 地址 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

### 4.5 审计日志表 (inventory_logs)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键，自增 |
| operation_time | DATETIME | 操作时间 |
| operator_id | INT | 操作人ID，外键 |
| operation_type | VARCHAR(20) | 操作类型：IN/OUT |
| product_id | INT | 商品ID，外键 |
| sku | VARCHAR(50) | 商品SKU（冗余） |
| quantity_change | INT | 数量变化（正为入库，负为出库） |
| quantity_before | INT | 变化前库存 |
| quantity_after | INT | 变化后库存 |
| supplier_id | INT | 供应商ID（入库时） |
| remark | VARCHAR(500) | 备注 |
