# 任务总结文档规范

## 概述

在每个任务阶段完成后，必须输出一份总结文档，记录本次任务的执行情况。

## 总结文档位置

- 文件路径：`docs/CHANGELOG.md`
- 如果文件不存在，创建新文件
- 如果文件已存在，将新内容追加到文件顶部（最新的在最前面）

## 总结文档格式

每次任务完成后，按以下格式追加内容：

```markdown
## [日期] 任务名称

### 执行概要
- **任务编号**：tasks.md 中的任务编号
- **执行时间**：开始时间 - 结束时间
- **执行状态**：成功 / 部分成功 / 失败

### 完成内容
简要描述本次任务完成了什么功能或目标。

### 文件变更
列出本次任务新增、修改、删除的文件：

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 新增 | path/to/file.ts | 文件用途说明 |
| 修改 | path/to/file.ts | 修改内容说明 |
| 删除 | path/to/file.ts | 删除原因说明 |

### 关键代码/配置
如有重要的代码片段或配置，简要列出。

### 遗留问题
如有未完成或需要后续处理的问题，在此记录。

### 下一步
建议的下一步操作或待执行的任务。

---
```

## 触发时机

在以下情况下必须生成/更新总结文档：

1. 完成 tasks.md 中的一个主任务（一级任务）
2. 完成一组相关的子任务
3. 遇到阻塞问题需要暂停时
4. 用户明确要求生成总结时

## 示例

```markdown
## [2026-01-21] 1. 项目初始化

### 执行概要
- **任务编号**：1.1 - 1.5
- **执行时间**：14:00 - 15:30
- **执行状态**：成功

### 完成内容
完成了 SmartStock 项目的基础框架搭建，包括前后端项目初始化、依赖安装、目录结构创建。

### 文件变更

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 新增 | backend/package.json | 后端项目配置 |
| 新增 | backend/tsconfig.json | TypeScript 配置 |
| 新增 | backend/src/app.ts | Express 应用入口 |
| 新增 | frontend/package.json | 前端项目配置 |
| 新增 | frontend/src/app/layout.tsx | Next.js 根布局 |

### 关键代码/配置
- Express 监听端口：3001
- Next.js 开发端口：3000
- 数据库连接配置已添加到 .env.development

### 遗留问题
无

### 下一步
执行任务 2：数据库表结构创建

---
```

## 注意事项

1. 总结要简洁明了，避免冗余
2. 文件变更列表要完整准确
3. 遗留问题必须如实记录，不要隐藏
4. 每次追加内容时，在顶部添加分隔线 `---`
